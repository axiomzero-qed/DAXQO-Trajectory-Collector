## 性能

相同弹窗开关工作负载，每种模式 8 次操作；两机指标取各自成功测量轮次。

| 指标 | Neo | K70 Pro |
| --- | --- | --- |
| 未采集时平均动作耗时 | 64.38 ms | 158.13 ms |
| 采集时平均动作耗时 | 218.63 ms | 289.25 ms |
| 差值 | +154.25 ms | +131.12 ms |
| DAXQO 全进程 PSS：未采集 / 采集 | 25,396 / 32,811 KiB | 50,937 / 49,117 KiB |

额外延迟包含为页面更新保留的 120 ms 等待。PSS 是整个既有 DAXQO 进程的短时观测，包含运行时和缓存波动，不能将差值当成采集器独立内存占用。

K70 的 FrameMetrics 在关闭采集时观察到 256 帧、9 次超预算帧；开启时 288 帧、70 次超预算帧；两轮指标回调丢失均为 0。这是 120 Hz 下的短时渲染预算指标，不是物理丢帧计数，也不代表所有业务 App 的性能。

Neo 的 gfxinfo 与 Window FrameMetrics 不提供有效帧样本。备用 Choreographer 估计在未采集/采集时分别观察 126/286 次 UI 回调、估计错过 5/2 个 vsync；它只反映 UI 调度间隔，不能代表 GPU 渲染耗时或物理丢帧。没有把不可用数据当成零丢帧。测量细节在 `dist/performance.json`。

## 数据与验证

独立采集验收接收 253 条记录；再加入真实模型及性能轨迹。与正在开发的 Motor 协调后，只读合并其独立接收库中的 159 条记录，保留所有原始本地审计数据。合并时的总量为 576 条、2 台设备、10 个任务；之后 Motor 可继续向共享目录追加。

Collector 初次交付的独立验证并去重评分导出有 42 条，含成功与失败样本；均来自隔离测试 App，并标注 `data_origin=fixture`。当时同一任务、重复转移及其所有关联来源形成一个防泄漏组，因此训练集 42 条、测试集为空。后续 Motor 联动增加了独立任务，最新数量见上方更新，未人为拆开相关轨迹。

本地自动测试 **48 项全部通过**，覆盖隐私、原生时间戳、幂等/冲突、崩溃尾行恢复、多实例索引、传输故障、批次连续性、反馈关联、分组防泄漏和只读合并。既有 0.4 后端回归 172 项（Windows 跳过 27 项）；0.5 后端 Windows 回归 176 项（跳过 27 项）。Neo 安全更新流程在手机 Linux 跑完 198 项测试，全部通过。

## 并行项目与边界

两份接收目录同时确认缓存会让旧目录看到跳号。最终复查中校验正确拒绝该批次；对应记录已从 Motor 完整持久库只读合并，并依据源收据将 Redmi 游标 481 接续至 640，未猜测单条序号。收据存于 `data/imports/`。

Motor 联调与取消验证期间独占两机操作和 ACK，共用 Collector 的 `data/`；目前已收到最终释放通知，可按单一驱动约定开展下一轮采集。不会用基础 Collector APK 覆盖 Motor 原生功能。采集未使用持续截图；没有开发模型训练模块。当前结果验证采集与评分接口，长时间真实业务任务和跨 App 泛化仍需后续数据积累。

JSON Schema 见 `schema/trajectory-v0.1.schema.json`；训练评分接口见 `docs/DATASET.md`；最新数据快照、导出清单及各项报告汇总为 `dist/final-summary.json`。运行 `python scripts/final_report.py` 可重新生成快照与回放。
